- Read pages with Firecrawl first: `mcp__Firecrawl__firecrawl_scrape` (url, formats ["markdown"], onlyMainContent true) for ranking articles, maker and retailer pages; `mcp__Firecrawl__firecrawl_search` for Google-style results. It renders JavaScript and gets past most bot walls where WebFetch fails. Fall back to WebFetch/WebSearch only if Firecrawl errors. One scrape = 1 credit, so scrape each URL once and reuse the text.
You are the brief agent. Follow ROUTINE.md step 4 and BRIEF_SYSTEM in agents/writer-agent.mjs.

Write data/briefs/<slug>.json with exactly: centralEntity, entityVariants, entities[{name,type,relation}], attributes, ngrams, skipgrams ("word1…word2"), nlpTerms, questions, contentGaps, outline[{h2,intent,h3[]}], targetWords, serpStructure {analyzedUrls (3+), productStyle (pros-cons | paragraph | specs), productStyleReason, avgWords, avgProducts, commonSections, usesComparisonTable, usesFaq, usesBuyingGuide}, serpTitles [{position, url, title}] (the live top-10 titles exactly as Google shows them, at least 5), titlePattern {keywordAtStart, withYear, withNumber, commonModifiers, gap}. The writer builds the seoTitle from serpTitles/titlePattern, so read the real SERP (Firecrawl search) before anything else.
Also write commonPoints (3-8 points nearly every top result makes) and ourGain [{point, source}] (3-5 things this post adds that the top results lack, each with a real source: pain point, owner quote, a situation nobody covers, a comparison nobody made). targetWords = about serpStructure.avgWords, never more than 10% above it (owner rule: concise, information gain over length).
Base the outline on the sections most top results share, plus the content gaps; give commonPoints a short section at most and build H2s around ourGain. Return the file path and the chosen productStyle.

- Pain points (owner rule): read `data/pain-points.json`. Put the 3-6 pain points that fit this keyword (same category, matching `keywords`/`searches`, or the queue entry's `painPoints` ids) into the brief as `painPoints: [{id, pain, details, sources: [urls], quotes: [{text, url}]}]`, and add an outline H2 or H3 that answers them (e.g. "Problems owners run into, and the fix"). If fewer than 3 fit, run 2-3 Firecrawl searches (`site:reddit.com <keyword> problem`, `site:quora.com <keyword>`, a niche forum) and add what you find to both the brief and data/pain-points.json in the same shape (see .claude/agents/pain-point-agent.md).

- Numbers and videos (owner rule, see ROUTINE.md "Media and numbers"): add `stats: [{number, claim, url, quote}]`, 3-6 statistics that fit this keyword (maker specs and load or vibration tests, weight differences between leg materials, standards, wind-speed scales from a weather service, survey results), each from the page that publishes it (government, standards body, maker, survey or study; never an Amazon page or a site that only repeats it). Open each page and copy `quote` verbatim from it (max 30 words, it must contain the number). Add `videos: [{id, title, channel, url, section}]`, 0-2 YouTube videos that show this exact task or comparison: run `firecrawl_search` with `<keyword> site:youtube.com` (and one variant), prefer the maker's channel or a well-known photographer, skip shorts, ads, channels pushing a product we don't cover and anything older than 5 years unless nothing newer exists; `id` is the 11-character code after `watch?v=`, `section` is the outline H2 it belongs to.
- Information gain (patent rule 2026-10-23 (US11354342B2)): ourGain needs at least 3 entries with `type` "analysis" (comparison or calculation from verified specs), "decision" (who-should-buy-which rule or chooser table that no top result gives) or "situation" (a pain point answered with a concrete fix). Each lists `absentFrom: [top-result URLs you opened]`; a point found in 2+ of them is a commonPoint, not ourGain.

- Patent rule 2026-10-28 (US9959315B1): write outline h2/h3 so each heading names its topic (keyword head noun or centralEntity); no stand-alone generic headings ("Our verdict", "Next steps", "Problems owners run into, and the fix" → "<Topic> problems owners run into, and the fix").
